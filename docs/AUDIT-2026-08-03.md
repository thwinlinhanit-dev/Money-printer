**Medium (ops) — watchdog's process-detection query kills its own collectors.**
Found while restarting: `ops/watchdog_collectors.ps1` checked liveness with
`Get-CimInstance Win32_Process` + a `CommandLine` filter. On this Windows box
that query **terminates the very collectors it enumerates** — every
watchdog-spawned collector exited `0xFFFFFFFF` exactly one check-interval
after spawn (20s interval → dead at 20–21s; 5s interval → dead at 6s), with no
Windows crash/WER record, while the identical binary spawned directly (or
under a heartbeat-only watchdog) ran indefinitely. Isolated via a no-CIM
watchdog variant (collectors survived 90s+, heartbeat-only) and an exit-code
capture (code −1 = TerminateProcess-style kill). Fix: watchdog now judges
liveness purely from the heartbeat file (written every 15s; restart if
stale > 75s) + data-log stall (> 150s), and kills only the tracked PID via
`Get-Process -Id` (plain native read, safe). Heartbeat staleness is the
stronger signal anyway (catches hung processes). Since the fix the two
collectors have run continuously with zero respawns; recorded as a Decision in
spec 019.
