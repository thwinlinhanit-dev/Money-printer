## Data inventory & integrity (follow-up to the code audit)

Audited `data/` (the actual collected asset) with `mp-audit` (spec 024 INT-1..5),
`inspect_log`, cold-store manifests, and Polars reads. Full detail in chat;
the load-bearing numbers:

**Critical — format fork on 07/30: ~9.5 GB (≈73% of raw) is currently unreadable.**
- `SCHEMA_VER` was bumped `1 → 2` in commit `c50f023` with **no migration path**
  (`core/src/log.rs` reader does a strict `schema_ver != SCHEMA_VER →
  UnsupportedSchema` reject). All logs written before 07-30 (`20260718` …
  `20260729`) are valid schema-1 files that `inspect_log`/`mp-audit` now refuse
  with `Error: UnsupportedSchema(1)`. Data is NOT corrupt — bytes are intact and
  the cold store proves schema-1 was fully readable on 07-26 (manifests built
  then show coverage 1.0). It is *frozen behind the version gate*.
- Files affected: every `2026-07-18 … 07-29` Binance/Bybit/HyperLiquid log
  (~7.9 GB inner + the 2.2 MB stray outer `data/raw/20260729…` copy).
- Only `20260730` + `20260731` (4 files, ~2.8 GB) parse; `mp-audit` verdict
  for those: coverage 0.99–1.0 but **every one DIRTY** — 1,523,538
  `sequence_gap` + 9,992 `recv_time_reversal` findings (~50% of events are
  gap-status records). The `20260730` BTCUSDT log is 356,191 book snapshots +
  only 674 deltas — the book-delta stream effectively never ran that day
  (C3 demote/re-seed churn).

**High — no recordings since 07-31; collector not running.** Last log is
`20260731`; last heartbeat `ts=1785540211` = **2026-08-01 05:53 UTC**; stale
lock files (`pid=9396`) remain; `tasklist` shows no collector. August 1–3 are
missing entirely. Collection must be restarted (and the stale locks removed)
for the dataset to keep compounding.

**High — data split across two directories on 07-29.** The repo's `data/raw`
has `20260729_binance_BTCUSDT.log` (17 MB — vs ~700–900 MB for a full day)
and a *second* `data/` sibling outside the repo (2.2 MB, own heartbeat/lock,
pid 16132) holds part of the same day. 07-29 BTCUSDT is ~2–3% complete and
fragmented; a duplicate collector run wrote to the wrong root.

**Medium — cold store is thin but readable.** `data/cold/trades/…` = 5 Parquet
files (BTCUSDT 07-20/22/23, ETHUSDT 07-22/23), 2,183,117 trade rows total
(verified via Polars), Hive-partitioned + manifests. Note 07-22 ETHUSDT
book_deltas coverage 0.49 with thousands of `venue` gaps recorded in the
manifest (honest, but that day's delta data is ~half missing). Compaction for
07-18..07-29 is impossible until the schema-1 read path is restored (INT-4
refuses quarantined input).

**Low — hygiene.** ~55 stray files in `data/raw/` (stdout/stderr captures,
`test_*.ps1`, `launch_*.bat`, `watchdog_*.log`, `*_err.log`); the old
`collector_binance_*.log` files are `BadMagic` (never event logs);
`collected.eventlog` (84 KB, 07-16) is schema-1 and likewise unreadable now.
