## Findings fixed this session (the 5 P2s from 08-06)

All five were re-confirmed present in the current code, then fixed and
verified green.

1. **`paper-tail` empty universe → carry-v1 silently never trades** — FIXED.
   `sim/src/bin/sim.rs` `paper-tail` built the strategy with `&[]`, so
   `carry-v1`'s `universe.symbols.contains(..)` gate was always false. Now the
   log's current contents are read once up front and the universe derived from
   them; the session is seeded with that batch (idempotent with the tail
   merge-key dedup). `sim/AGENTS.md` updated.
2. **`ws_probe.mjs` misclassifies a SUBSCRIBE *error* as an ack (fail-open)** —
   FIXED. The ack gate was `j.id === 1 && !j.e`, so `{error, id:1}` exited 0.
   Now a `{error}` response sets `subscribeRejected` and exits 2; only the
   success shape `{result, id}` counts as an ack. `ops/AGENTS.md` updated.
3. **`post_p1_webhook` echoes curl stderr (URL/token leak, PD-2)** — FIXED.
   The failure branch returned curl's stderr verbatim; on transport errors
   stderr can embed the webhook URL (which may carry a sink token). Now it
   reports only the exit code. `ops/AGENTS.md` updated.
4. **`engine_git_sha` in the W-6 content hash blocks metadata-only
   re-materialization** — FIXED. Removed `engine_git_sha` from
   `rows_content_hash`; it remains in the FEA-6 footer (round-trip asserted).
   Spec 016 + `storage/AGENTS.md` updated.
5. **`resolve_version` ignored `feature_ver`** — FIXED. The version-directory
   identity is now `params_hash:feature_ver`, so a feature-code upgrade opens a
   new `ver=N` (FEA-6) instead of reusing `ver=0` and tripping the W-6 guard.
   Legacy bare-`params_hash` markers still match when `ver == feature_ver`, so
   existing stores stay resumable. Spec 016 + `storage/AGENTS.md` updated.
