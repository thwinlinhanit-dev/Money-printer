# Honest ideas — after v1, not instead of it

**Date:** 2026-08-31
**Rule:** nothing here jumps `docs/COMPLETION-MASTER-PLAN.md`. Ideas enter
`docs/BACKLOG.md` then a numbered spec (PD-6). This file is judgment, not
a queue.

The lab already has more *intelligence surface* than *evidence*. The
useful ideas are the ones that increase **trust** or **one slow edge**,
not another dashboard.

---

## A. Ideas I would actually build (ranked)

### 1. Single-host canonical scoring (ops)

If drain SSH keeps failing, **score on the VPS** and copy 20 KB of JSON
home. The Windows machine becomes a research workstation, not a link in
the integrity chain. This is the highest-leverage architecture change
still unmade. It needs an owner nod (050 open question).

### 2. Funding-arb as a hedged pair, not a vibe

The only idea with a green feasibility stamp. Build the smallest
executable: two venues, BTC only, hold when |spread| exceeds a band,
exit on mean reversion or time-stop, **spot or inverse-perp hedge
explicit**. If you cannot collect a tradable second leg, keep it `held`.
Do not proxy with mark-oracle and call it carry.

### 3. Burst as a first-class instrument

The 3h20m Hyperliquid WS stall is not a random dirty day — it is a
periodic hole. Treat it as a **collector SLO**: alert when the rotation
is late, not only when the day ends dirty. A 15s stall detector already
exists; a *predicted* stall window (venue connection recycle) would let
you discount those minutes in research instead of throwing out the day
or pretending coverage is 1.0 with bursts in a side file.

### 4. “Would BTC have beaten this?” as a daily number

OWNER_POLICY already names buy-and-hold BTC as the benchmark. The weekly
review still printed `unset` in W34. Ship a 20-line job: paper (or
strategy) expectancy vs BTC holding over the same window. If you cannot
beat doing nothing in BTC, the machine is an expensive recorder — which
is still valuable, but you should see the number every morning.

### 5. Kill the second research stack

Python `run_v2_backtest_*.py` + Pine + Rust sim is three truth sources.
v1 rule: **Rust sim is the only number that may promote**. Python is for
event studies and plots. Pine is a sketchbook. When they disagree, Rust
wins or the test is broken.

### 6. Paper on a *null* strategy for one week

Before swing-range-reclaim, run `NullStrategy` paper for 7 days. You are
proving the rehearsal harness, not alpha. Cheap, honest, and it will
surface latch/telegram/journal bugs without a random PnL story.

## C. Product thesis (if this stays a solo fund-of-one)

The machine should feel like:

1. **Morning:** console is green or screaming. You never wonder if
   yesterday existed.
2. **Weekly:** one table — ideas killed, one active, BTC benchmark.
3. **Rarely:** a strategy survives paper. Then you *discuss* live-small.

That is a complete app. A footprint heatmap is a hobby overlay.

If you only do three things after reading the audit: **fix the gate,
move the data, run paper on null**. Everything else is optional
intelligence.
